# 05 — Dependency Baseline

All versions are the exact resolved versions in `pnpm-lock.yaml` at the end of Phase 1 (confirmed via
`pnpm list --depth 0`). Every package was selected by checking the npm registry directly during this
phase (not assumed from prior knowledge), and cross-checked against `create-next-app`'s own scaffold
choices where relevant — see `01-engineering-foundation.md` §8–9 for the reasoning behind the two
version decisions that diverged from "always pick the newest."

## 4. Licensing / Security Notes Discovered

- No package in the dependency tree was flagged with a license incompatible with a private, unpublished
  application (all core dependencies — Next.js, React, Supabase's client libraries, Vitest, Testing
  Library, Zod, Prettier, ESLint — are MIT-licensed, which is the standard expectation for this part of
  the JavaScript ecosystem; no unusual or restrictive license was encountered).
- `pnpm install` printed one dependency warning during this phase: `1 deprecated subdependencies found:
tsconfck@3.1.6` (a transitive dependency, pulled in via the tooling chain, not a direct dependency of
  this project). It does not affect any Phase 1 functionality — install, lint, typecheck, test, and
  build all succeed — and is noted here rather than silently ignored. Re-evaluate if it starts producing
  an actual warning or error in a future `pnpm install`.
- No `pnpm audit`-equivalent scan was run this phase — see `04-quality-and-ci.md` §8 for why, and when
  it's planned to start.
- The real, verified issue this phase surfaced was **not** a licensing or security problem but a
  runtime-compatibility one (`jsdom@30` vs. Node 20.19.0, §2 above) — recorded in detail because it is
  exactly the kind of thing a future `pnpm update` could silently reintroduce without this note.

## 5. Intentionally Deferred Dependencies

Not installed in Phase 1, on purpose — each belongs to a specific later phase per
`docs/phase-0/10-product-roadmap.md`:

| Dependency (not installed)                                       | Deferred to                                                              | Reason                                                                                                                                                                     |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Any decimal/money math library (e.g. a `Decimal`/bignum package) | Phase 3 (Accounts and Ledger)                                            | Fixed decision requires decimal-safe money handling (`docs/phase-0/09-architecture-decisions.md` ADR-13), but no monetary value exists in the codebase yet to apply it to. |
| Any AI provider SDK                                              | Phase 12 (Explainable AI Insights)                                       | No AI feature exists yet; Phase 0 requires AI providers to remain replaceable via a provider-adapter, which will shape _how_ this is eventually added.                     |
| Any market-data/broker provider SDK                              | Phase 8+                                                                 | No investment feature exists yet.                                                                                                                                          |
| Any state-management library (Zustand/Redux/etc.)                | Not yet decided                                                          | The foundation page has no client state; nothing has demonstrated a need for one yet, and adding one pre-emptively would be scope creep.                                   |
| Any UI component library                                         | Not yet decided (final design system is explicitly out of Phase 1 scope) | The brief explicitly prohibits "no premature component library" in Phase 1.                                                                                                |
| `prettier-plugin-tailwindcss` (class-sorting)                    | Not scheduled                                                            | A genuine convenience, but an extra dependency with no functional necessity — left out to keep Phase 1's tooling surface to what's actually needed.                        |
| E2E testing framework (e.g. Playwright)                          | When real user journeys exist                                            | Per the brief: don't add broad E2E infrastructure before there's something meaningful to test end-to-end.                                                                  |
